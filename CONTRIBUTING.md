# Contributing

Thanks for helping out. Here's how a change gets from idea to `main`.

1. **Start with an issue.** Even small fixes get one, so the reason sticks around.
2. **Branch from `main`.** Name it after the issue: `14-short-summary`.
3. **Open a pull request.** Fill in the template and include `Closes #14`.
4. **Title it `type: summary`.** Pull requests are squash-merged, so the title and description become the commit on `main`.
5. **Fixes come with a test.** Write it first, watch it fail, then make it pass.
6. **Keep it public-safe.** No tokens, hostnames, paths or personal details in code, issues or pull requests.

Found a security problem? Please don't open an issue. See [SECURITY.md](SECURITY.md).
